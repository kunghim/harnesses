# ADR 0001 · 从 Git 资料源生成不可变快照

状态：提议。日期：2026-11-13。

## 背景

harnesses 以来源可追溯的产品与规则资料为核心。编辑频率低于查询频率，变更须审阅。网页、整库 JSON、API 和 MCP 需要一致的事实、条件和版本。收录规模增加时，下载体积和查询索引会分别增长。

## 决策

贡献通过 Git 中分实体和模块的 JSON 文件提交。CI 校验关系、规则、证据与数据格式，生成固定快照。Astro 静态生成网页，一个 Worker 版本固定当前快照，HTTP 与 MCP 共用查询模块。R2 保存固定快照和大文件。

## 比较

| 方案 | 取舍 |
| --- | --- |
| 单个手改 JSON | 初始结构简单。多人编辑、跨实体引用审查和按需读取随规模变难 |
| 资料数据库和管理后台 | 支持实时编辑与复杂查询，需要增加写入服务、权限和审计 |
| 分文件资料源与构建快照 | 贡献变更便于审阅，消费者可以锁定版本。资料更新经过一次构建和发布 |

## 后果

查询可以使用无状态服务，部署和回退有明确的快照标识。构建、差异比较和 CI 需要额外实现。若索引超过体积预算或预览性能不达标，先分片或添加读模型，沿用相同数据契约。若边缘部署受限，可以在 Node 服务上替换 Worker 适配层，保留静态页与版本化产物。

验收以[技术方案](../architecture.md)中的快照一致性和性能预算为准。
